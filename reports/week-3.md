## A. 지난주 액션 결과

### 2주차에 정한 액션

대소변 감지에 더해, 반려견이 배변 패드 위에 올라왔는지까지 감지하는 기능을 시도한다.

단순히 "배변했다"는 결과만 기록하는 것이 아니라, 패드 방문 여부와 배변 여부를 함께 기록하여 반려견의 배변 패턴을 더 자세히 파악할 수 있도록 하는 것이 목표였다.

### 실행 상태

- 진행 중
    - 기능 구현은 완료했지만, 방문 감지와 대소변 감지 모두 정확도 조절이 더 필요한 상태이다.

### 결과

다만 기술적으로는 패드 방문 여부와 대소변 감지 데이터를 함께 수집할 수 있는 흐름을 구현했지만 아직 유저 테스트를 진행하지 못해 실제 사용자에게 효과가 있었는지는 판단하기 어렵다.

## B. 개발 진행 상황

### 이번 주에 만든 핵심 기능

1. 패드 방문 감지 기능
2. 대소변 감지 기능
3. 아두이노 감지 데이터를 Supabase에 저장하는 기능
4. 앱에서 DB에 저장된 배변 기록을 조회하고 보여주는 기능
5. 사용자가 직접 기록을 추가하는 기능

### MVP 진도

| 1주차 MVP 범위        | 현재 상태            |
|-------------------|------------------|
| 대변 감지 기능          | 구현 완료, 정확도 조절 필요 |
| 소변 감지 기능          | 구현 완료, 정확도 조절 필요 |
| 방문 감지 기능          | 구현 완료, 정확도 조절 필요 |
| 모바일 앱을 통해 기록 보여주기 | 구현 완료 및 기능 확장 중  |

### 발표에서 보여줄 수 있는 핵심 흐름

아두이노가 패드 방문 여부와 대소변 감지 결과를 측정한 뒤, 해당 데이터를 Supabase DB로 전송한다.
이후 CMP 앱에서 DB에 저장된 기록 데이터를 불러와 사용자에게 배변 기록으로 보여준다.

즉, 현재 발표에서는 다음 흐름을 시연할 수 있다.

아두이노 감지 → Supabase 저장 → CMP 앱에서 기록 조회

### 범위 변경

#### 늘어난 것

- 사용자가 배변 기록을 직접 추가하는 기능

#### 줄어든 것

- 아직 없음

#### 변경 이유

아두이노가 배변 이벤트를 정확하게 감지하지 못했을 경우를 대비하기 위해 수동 기록 기능을 추가했다.

또한 반려견이 배변 패드가 아닌 다른 곳에 배변했을 때도 사용자가 기록을 남길 수 있어야 한다고 판단했다.
이를 통해 자동 감지 데이터만으로는 부족할 수 있는 기록의 완성도를 높이고, 병원 방문이나 건강 상태 확인 시 더 신뢰도 있는 기록으로 활용할 수 있도록 했다.

## C. 의사결정 / 막힘

### 새로 발견한 문제

사용자 정보를 별도로 관리할지에 대한 고민이 생겼다.

초기에는 Authentication과 User 테이블을 두고 사용자별 기록을 관리하는 방향도 고려했지만, MVP 단계에서 이 구조가 꼭 필요한지 판단이 필요했다.

### 결정

MVP에서는 Authentication과 User 테이블을 제외하기로 결정했다.

### 근거

현재 서비스의 핵심은 사용자 계정 관리보다 아두이노 기기에서 발생한 배변 감지 데이터를 안정적으로 저장하고 앱에서 보여주는 것이다.

또한 아두이노 기기의 고유 ID를 기준으로 데이터를 구분할 수 있기 때문에, MVP 단계에서는 별도의 유저 테이블 없이도 기록 관리가 가능하다고 판단했다.

따라서 이번 단계에서는 사용자 인증 구현보다 감지 정확도 개선과 기록 흐름 검증에 더 집중하기로 했다.

## D. 회고

### 이번 주 가장 큰 학습

이번 주에는 Supabase를 처음 사용해 보면서, 백엔드 서버를 직접 크게 구현하지 않아도 DB 연동과 이벤트 저장 흐름을 빠르게 만들 수 있다는 점을 알게 되었다.

특히 Supabase가 SQL 기반으로 동작하기 때문에 테이블 구조를 이해하고 데이터를 확인하기 쉬웠고, MVP를 빠르게 검증하는 데 적합하다고 느꼈다.

또한 아두이노 코드를 처음 작성하면서 센서 값을 읽고, 조건에 따라 이벤트를 판단하고, 이를 DB로 전송하는 전체 흐름을 경험할 수 있었다.

CMP 역시 처음 사용해 보면서 하나의 코드 기반으로 모바일 앱 UI와 데이터 연동을 구현하는 흐름을 익힐 수 있었다.

### 지금 가장 의심스러운 가정

현재 기능만으로 실제 사용자가 충분한 가치를 느낄 수 있을지 아직 확신하기 어렵다.

특히 단순히 배변 여부를 알려주는 것만으로는 사용자의 지속적인 사용을 이끌어내기 어려울 수 있다고 생각한다. 따라서 배변 기록이 건강 관리나 병원 상담, 노령견 관리와 연결될 때 더 큰 가치가 생길 수 있을지 검증이
필요하다.

또한 패드를 교체하지 않은 상태에서 대소변 이벤트가 여러 번 발생했을 때, 각각의 이벤트를 정확히 구분할 수 있을지도 의심되는 부분이다.

예를 들어 이미 소변이 묻은 패드 위에 다시 소변을 보거나, 대변과 소변이 시간차를 두고 발생했을 때 센서 값만으로 새로운 이벤트를 안정적으로 구분할 수 있는지 추가 테스트가 필요하다.

### 최종 발표 흐름 초안

최종 발표에서는 문제 상황, 감지 방식, 데이터 저장 흐름, 앱 기록 화면, 그리고 MVP 테스트 결과를 중심으로 발표할 예정이다.
